Code Block Feature Demo

A self-contained reproduction of the code block highlighting and styling pipeline used on abhinavsarkar.net. Three features are demonstrated:

  1. Client-side syntax highlighting + line numbers via highlight.js
  2. Full-viewport-width breakout of code blocks beyond the article column
  3. Build-time line-range emphasis via the emphasizeCode Pandoc transform

1 — Standard code block (highlight.js + line numbers + breakout)

highlight.js detects the language from the language-haskell class and tokenises the block client-side. The line-numbers plugin restructures it into a two-column table (td.hljs-ln-numbers / td.hljs-ln-code). styleCode() then offsets the <pre> leftward with a negative left value equal to its own viewport offset, stretching it to full window width while keeping the code text column-aligned via compensating margin-left on the inner <code>. 

module Site.PostCompiler where

import Data.Maybe        (fromMaybe)
import Hakyll            hiding (relativizeUrls)
import Site.ERT
import Site.Pandoc.Compiler
import Site.Util
import System.FilePath.Posix (takeBaseName)

-- | Entry point for both published posts and drafts.
doCompilePosts :: Bool -> Bool -> Tags -> String -> [Identifier] -> Rules ()
doCompilePosts mentionsEnabled commentsEnabled tags env posts = compile $ do
  post      <- getUnderlying
  alignment <- fromMaybe "left" <$> getMetadataField post "toc"
  path      <- getResourceFilePath
  let postSlug = takeBaseName path

  comments <- sortComments
    =<< loadAllSnapshots (fromGlob $ "comments/" <> postSlug <> "/*.md") "comment"
  let commentCount = show $ length comments

  sortedPosts <- sortChronological posts
  nextCtx     <- navLinkCtx "next_post" $ sortedPosts `itemAfter`  post
  prevCtx     <- navLinkCtx "prev_post" $ sortedPosts `itemBefore` post

  content <- readContentWithPandoc
  let ert = timeEstimate . itemBody $ content

  void $ makeItem ert          >>= saveSnapshot "ert"
  void $ makeItem commentCount >>= saveSnapshot "comment_count"

  let ctx = postCtxWithTags tags
         <> nextCtx <> prevCtx
         <> constField "post_slug"     postSlug
         <> constField "post_ert"      ert
         <> constField "comment_count" commentCount
         <> boolField  "comments_enabled" (const commentsEnabled)
         <> boolField  "live_reload"      (const $ env == "DEV")

  pandocItemCompiler (postContentTransforms postSlug alignment) content
    >>= saveSnapshot "content"
    >>= loadAndApplyTemplate "templates/post.html"    ctx
    >>= loadAndApplyTemplate "templates/default.html" ctx
    >>= relativizeUrls env
    >>= removeIndexHtml

2 — Go block (concurrency example)

This example demonstrates a small concurrent worker pool written in Go. highlight.js will detect language-go and apply syntax highlighting automatically. 

package main

      import (
        "context"
        "fmt"
        "math/rand"
        "sync"
        "time"
      )

      type Worker struct {
        ID int
      }

      func (w Worker) Process(ctx context.Context, jobs <-chan int, results chan<- int, wg *sync.WaitGroup) {
        defer wg.Done()
        for {
          select {
          case <-ctx.Done():
            fmt.Printf("[worker-%d] shutting down\n", w.ID)
            return
          case job, ok := <-jobs:
            if !ok {
              return
            }
            sleep := time.Duration(rand.Intn(300)+100) * time.Millisecond
            time.Sleep(sleep)
            results <- job * job
          }
        }
      }

      func main() {
        rand.Seed(time.Now().UnixNano())

        ctx, cancel := context.WithTimeout(context.Background(), 3*time.Second)
        defer cancel()

        jobs := make(chan int)
        results := make(chan int)

        var wg sync.WaitGroup

        // Start workers
        for i := 0; i < 3; i++ {
          wg.Add(1)
          go Worker{ID: i}.Process(ctx, jobs, results, &wg)
        }

        // Feed jobs
        go func() {
          for i := 1; i <= 10; i++ {
            jobs <- i
          }
          close(jobs)
        }()

        // Close results after workers finish
        go func() {
          wg.Wait()
          close(results)
        }()

        sum := 0
        for r := range results {
          sum += r
        }

        fmt.Println("Final sum:", sum)
        }

2 — JavaScript block (language auto-detection)

The site loads a dedicated Haskell language pack alongside the highlight.js core. Other languages use the built-in packs bundled with the core. Below is the actual styleCode() / unstyleCode() implementation from js/post-styling.js that drives the breakout effect above. 

(function () {
  function styleCode() {
    var ww = jQuery(window).width();
    var bw = jQuery('main article').width();

    // Shift each 
 to the left edge of the viewport.
    jQuery('article pre').each(function () {
      if (jQuery(this).parents('section.footnotes').length === 0) {
        var margin = jQuery(this).offset().left;
        jQuery(this).css('left',  '-' + margin + 'px');
        jQuery(this).css('width', ww + 'px');
      }
    });

    // Re-indent the inner  so its text aligns with the article body.
    jQuery('article pre code').each(function () {
      if (jQuery(this).parents('section.footnotes').length === 0) {
        var margin = jQuery(this).offset().left;
        jQuery(this).css('margin-left',  margin + 'px');
        jQuery(this).css('margin-right', (ww - margin - bw) + 'px');
      }
    });
  }

  function unstyleCode() {
    jQuery('article pre').each(function () {
      jQuery(this).css('left', 'auto').css('width', 'auto');
    });
    jQuery('article pre code').each(function () {
      jQuery(this).css('margin-left', 'auto').css('margin-right', 'auto');
    });
  }

  function restyleOnResize() {
    clearTimeout(window.resizedFinished);
    window.resizedFinished = setTimeout(styleCode, 250);
  }

  jQuery(document).ready(function () {
    styleCode();
    jQuery(window).resize(restyleOnResize);
  });

  // Reset layout for print, restore after.
  window.onbeforeprint = unstyleCode;
  window.onafterprint  = styleCode;
}());


      
      
3 — Build-time line-range emphasis (emphasizeCode)

      

        The emphasizeCode function in Site/Pandoc.hs
        is a Pandoc AST transform that runs at build time, before any browser
        JS is involved. It matches CodeBlock nodes annotated with
        an emphasize=<ranges> attribute, parses the range
        via pandoc-emphasize-code, and wraps those lines in
        <mark> tags inside Pandoc's own token span markup.
        The result is baked into the static HTML.
      

      

        Because highlight.js v9's highlightBlock reads
        element.textContent and rewrites innerHTML
        wholesale, it would destroy the <mark> tags. The
        emphasizeCode feature therefore operates on the
        no-JS / Pandoc-native-highlighting path. The block
        below replicates the static HTML the pipeline would emit for
        emphasize=5-7 (lines 5–7 highlighted):
      

      
      
module Site.Pandoc where

import Data.List ((\\))
import Text.Pandoc.Definition
import qualified Text.Pandoc.Filter.EmphasizeCode.Parser   as EC
import qualified Text.Pandoc.Filter.EmphasizeCode.Chunking  as EC
import qualified Text.Pandoc.Filter.EmphasizeCode.Renderable as EC
import qualified Text.Pandoc.Filter.EmphasizeCode.Html      as EC

-- | Wrap specified line ranges in <mark> at build time.
--   Runs as a Pandoc AST walk before HTML is written.
emphasizeCode :: Block -> Block
emphasizeCode cb@(CodeBlock (id', classes, attrs) contents) =
  case lookupRanges attrs >>= (EC.runParser . EC.parseRanges) of
    Just (Right ranges) ->
      EC.renderEmphasized (EC.Html EC.Mark)
        (id', classes, filter (\(k, _) -> k /= "emphasize") attrs)
        $ EC.emphasizeRanges (EC.splitRanges ranges) (Text.pack contents)
    _ -> cb
emphasizeCode x = x



      
4 — No-JS fallback

      

        When JavaScript is absent, <html class="no-js">
        stays set. The _syntax.scss stylesheet applies Pandoc's
        token-span colours under .no-js selectors (e.g.
        .no-js code span.kw). Dark mode is handled with a blanket
        filter: invert(80%) rather than per-token overrides, since
        fine-grained dark theming requires the dynamically loaded highlight.js
        theme CSS. Disable JavaScript in your browser to see this path in
        action for examples 1 and 2 above — they will fall back to unstyled
        monospace text since their HTML contains no pre-tokenised Pandoc spans.
        Example 3 will continue to display correctly as it is already
        Pandoc-tokenised static HTML.
